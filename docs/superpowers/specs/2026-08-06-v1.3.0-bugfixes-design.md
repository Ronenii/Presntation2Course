# v1.3.0 — Bug-fix batch — Design

**Date:** 2026-08-06
**Status:** Approved

## Context

Three bugs surfaced by reviewing a real generated course
(`unit1_lecture_tutorial-course`, building-footprint-extraction, built under
v1.2.3). All three are traced to a specific root cause in the generator
(never in the course's own content), verified against the actual code and,
for the animation bug, a real headless-Chromium run of the built HTML (no
browser was available in earlier sessions; one was set up for this
investigation by extracting the missing shared libraries from `.deb`
packages into a user-writable directory — no root needed, nothing installed
system-wide).

This is the first of several independent pieces planned for v1.3.0 (the
others — new source/target languages, non-slide source formats, and
cheaper token usage — will each get their own brainstorm/design/plan cycle).

## Bug 1: jargon term reveal breaks on repeat mentions

**Symptom:** clicking a highlighted jargon term expands its definition the
first time it appears in a course, but clicking a later occurrence of the
same term does nothing visible.

**Root cause:** `glossary.py`'s `term_ids()` assigns exactly one `id` per
*term* for the whole course (e.g. `def-u-net`). `TermInjector.inject()` is
called once per topic and wraps that topic's first occurrence of each term
in a reveal control — but every topic's control references the same shared
`def_id`. A course where "U-Net" appears in many topics ends up with a dozen
DOM elements all sharing `id="def-u-net"`. `document.getElementById()`
(what `wireTerms()` in `course.js` uses to find the definition to toggle)
always resolves to the *first* one in document order, so clicking a control
in a later topic silently toggles a hidden `<span>` sitting elsewhere on the
page — invisible, reads as "nothing happened." Confirmed directly: the real
course's built HTML has `id="def-u-net"` repeated 12 times.

**Fix:** `TermInjector` gains its own `AnchorAllocator` (the same
collision-suffixing mechanism headings and appendix glossary ids already
use). Each inline injection calls `allocator.take(canonical_id)` — where
`canonical_id` is the term's existing appendix id from `ids[term.lower()]`
— to get a fresh, guaranteed-unique id for *that occurrence's*
button+definition-span pair (`def-u-net`, `def-u-net-2`, `def-u-net-3`, ...).
The appendix (`glossary_html`) is untouched: it keeps using the plain
canonical id, so `#glossary` anchors and the `<dt id="...">` entries are
unaffected. No grammar/schema change; no new files.

## Bug 2: definition popup renders too thin

**Symptom:** the expanding definition box sometimes renders as an oddly
narrow column, wrapping nearly every word onto its own line (see the
reported screenshot).

**Root cause:** `.term__def` (`assets/base/layout.css`) is
`position: absolute` with `inset-inline-start: 0` and `max-inline-size: min(24rem, ...)`
set, but no minimum width. An absolutely positioned block with only one
inset set shrinks to fit its content — for a short definition (a few words),
that content-fit width is very narrow, so the text wraps aggressively.

**Fix:** add `min-inline-size: min(16rem, calc(100vw - 2 * var(--space-4)))`
to `.term__def`, giving it a sensible floor without changing the existing
ceiling (`max-inline-size`) or the mobile centered-popup override, both left
as-is.

## Bug 3: step-reveal doesn't read as "animation"

**Symptom:** reported as "no animations at all"; on investigation (real
headless-browser trace), the mechanism was confirmed working exactly as
built — each list item's opacity/font-weight pulses in sequence — but the
user's own assessment, once shown the trace, was that this doesn't actually
work as an *animation*: every item is already fully visible as plain text;
highlighting one at a time in place is materially the same experience as
just reading the list top to bottom. It doesn't create motion or reveal
anything the reader didn't already have.

**Decision: retire `step-reveal` entirely**, replaced by a new pattern,
`state-machine` — a genuine diagram (labeled state boxes connected by
static arrows) with a marker that visibly travels from state to state as
each transition fires, and an action label that appears only for the
duration of that transition (not shown at rest). This is real motion tied
to a real structural change (which state is "current"), not the old
pattern's stand-still highlight.

`step-reveal` is removed from `HANDLED_KINDS`'s pattern set, its grammar
branch, its renderer, its CSS, and its course-writer documentation —
replaced by `state-machine` in every one of those places. No coexistence:
anything that would have used step-reveal instead becomes a state-machine
(a linear "first X, then Y, then Z" narration *is* a chain of trivial
one-input, one-output states — `A -> B: <what happens> -> C -> ...`).

### `state-machine` grammar

````
```animate
pattern: state-machine
states:
  - Encoder sees only visible patches
  - Decoder gets encoder output + placeholder tokens
  - Reconstruction compared to real pixels
transitions:
  - Encoder sees only visible patches -> Decoder gets encoder output + placeholder tokens: encode
  - Decoder gets encoder output + placeholder tokens -> Reconstruction compared to real pixels: decode + compare
```
````

- `states:` — an ordered list of state labels (short phrases, like
  `step-reveal`'s old `steps:` list). At least 2 states, matching every
  other pattern's "at least 2" floor.
- `transitions:` — one line per edge, `<from> -> <to>: <action label>`. At
  least 1 transition is required (a `states:` list with no `transitions:`
  is rejected — a diagram with nothing ever animating is not a valid
  state-machine block).
  `<from>`/`<to>` must exactly match two entries in `states:`. Every
  transition must connect **consecutive** states in the `states:` list
  order (`states[i] -> states[i+1]`), **except** one optional final
  transition from the *last* state back to any *earlier* state (a real,
  authored cycle — e.g. a retry loop) — the only case where a non-adjacent
  edge is permitted. This keeps the layout a straight chain (see below)
  while still allowing a genuinely cyclic process to say so honestly.
  `parse_animate` raises `AnimateError` for any transition that is neither
  adjacent-consecutive nor this one permitted back-edge.
- No `before:`/`after:`/`array:`/`ops:`/`points:`/`caption:` lines (same
  mutual-exclusion style already enforced for every other pattern).

**Why not allow branching (a state with 2+ outgoing transitions):**
considered and rejected. A single continuous animated marker cannot
meaningfully "choose" a branch to demonstrate every loop, and a full tour of
every edge produces a confusing, hard-to-follow visit order. Restricting to
a linear chain (with the one optional authored back-edge) keeps the
animation's meaning unambiguous: it always shows the one real path through
the process, in the order the course-writer described it.

### Rendering

`_state_machine_html(anim, token)` replaces `_step_reveal_html`:

1. **Static SVG chrome**, computed deterministically from `states`/
   `transitions` (same "Python emits data + geometry, never guesses"
   convention as `array-ops`/`path-trace`):
   - One rounded-rect box per state, laid out in a single left-to-right row
     (RTL-aware: mirrored for RTL courses, matching `array-ops`'s existing
     bar-order convention — this is diagram *structure*, not prose, so it
     follows the same `dir="ltr"`-wrapper precedent already used for every
     other animate/mermaid diagram), each with its label text centered
     inside.
   - One static arrow (line + arrowhead marker) between every pair of
     consecutive boxes, always visible — this is the diagram's permanent
     structure, like `array-ops`'s bars or `path-trace`'s plotted points.
     The optional back-edge (last state to an earlier one) is drawn as a
     curved arrow arcing below the row, visually distinct from the forward
     chain, so it reads as "this can loop back," never as a straight
     continuation.
   - One `<text>` per transition for its action label, **initially
     empty/hidden** (`opacity: 0`) — the label only becomes visible for the
     duration its transition is actively animating (see timeline below).
   - A small marker circle, initially positioned at the first state's box.
2. **Timeline JSON**, one step per transition, in `transitions:` order:
   - The marker tweens from the source box's position to the target box's
     position (reusing the exact `path-segment` step-kind machinery
     `path-trace` already established — a tweened `{x, y}` state object
     mirrored onto the marker's `cx`/`cy` via `onUpdate`; no new JS step
     kind needed).
   - That transition's action-label `<text>` fades in at `onBegin` and back
     out at the step's end (a `props.opacity` keyframe pair on the same
     step, targeting the label element alongside the marker's tween —
     `wireAnimations()` already supports multiple `targets`/props per
     step, no interpreter change needed).
   - The arriving state's box gets a brief highlight (`stroke`/`fill`
     shift to `--color-accent`, matching the existing accent-color
     convention) for the hold beat at that state, then settles back to
     idle before the next transition begins — signalling "this is now the
     current state" the same way `array-ops`'s highlight step does.
   - After the last transition, a hold beat, then (if there is no authored
     back-edge) an invisible reset: the marker's position is `set` (not
     tweened) back to the first state and every box/label snapped to idle,
     exactly mirroring `state-toggle`'s existing "trailing `kind: set` step"
     convention for resetting before a loop restarts. This is the
     mechanism that guarantees a finite chain never *appears* to loop back
     to the start — the restart is an invisible cut, not a visible
     "final -> first" arrow, matching the standing rule that only authored
     transitions are ever drawn or animated as edges.
   - If there *is* an authored back-edge, it is simply the last item in
     `transitions:` and plays like any other transition — the loop restart
     coincides with a real, visible, labeled arrow, which is exactly what
     makes it an honest cycle rather than a finite chain.
3. **Static fallback** (`prefers-reduced-motion`/print): a new
   `.anim__state-steps-static` plain-text ordered list, hidden by default
   and shown only in those two contexts (mirroring
   `.anim__array-steps-static`/`.anim__path-steps-static` exactly) — one
   line per transition: "`<from>` — `<action>` — `<to>`."

### CSS

`assets/base/layout.css`: remove `.anim__steps`/`.anim__step`/
`.anim--step-reveal`-scoped rules; add `.anim--state-machine` chrome
(box/label/arrow/marker styling, idle vs. highlighted box state, hidden vs.
visible label state) plus `.anim__state-steps-static { display: none; }`.
`assets/print.css`: remove the (nonexistent — step-reveal never needed one)
step-reveal print rule; add the `.anim__state-steps-static` print-visible
rule alongside the existing array/path ones.

### Docs

`references/agents/course-writer.md`'s animate decision test (added by the
earlier six-bugs fix round) currently reads: "does explaining the idea out
loud require 'first... then...' — if yes, use `step-reveal`." This is
rewritten to route that same case to `state-machine` instead, with the
grammar above documented alongside the other three patterns.

## Testing

Same test-philosophy constraints as every prior animate-library change:
dataclass equality for `parse_animate`, literal HTML/JSON substring/
`json.loads`-comparison assertions for rendering, golden whole-file
snapshots regenerated once at the end.

- `tests/test_mdrender.py`: remove step-reveal's parse/render tests; add
  state-machine equivalents — valid linear chain, valid chain-plus-back-edge,
  and each rejected shape (non-adjacent forward transition, unknown state
  name in a transition, fewer than 2 states, wrong mutual-exclusion fields
  present) each raising `AnimateError`. Render tests assert exact static
  SVG markup (box positions, arrow paths, back-edge curve) and exact
  timeline JSON (per-transition marker tween + label fade-in/out + box
  highlight + trailing `set`-or-real-back-edge), plus the reduced-motion/
  print static-list fallback text.
- `tests/test_assets.py`: update the DOM-contract test's pattern-name list
  (`step-reveal` out, `state-machine` in).
- `tests/test_build.py`: no change expected beyond whatever golden-file
  regeneration requires — the `uses_animate`/`inline_anime` wiring is
  pattern-agnostic already.
- `tests/golden/course.html` / `course-he.html`: regenerated via
  `P2C_UPDATE_GOLDEN=1` once all code/CSS changes land, reviewed line-by-line
  before committing (existing project discipline).
- Bugs 1/2 get straightforward new/updated unit tests: a fixture with the
  same term appearing in two topics, asserting the two rendered ids differ
  and the appendix id is unchanged; a CSS assertion (or visual note, since
  this project doesn't do pixel testing) that `.term__def` has the new
  `min-inline-size` rule.
- No new manual-smoke-test *requirement* beyond what's already standard,
  but given this whole investigation started from a live-browser find, a
  live-browser spot-check of the new state-machine pattern (linear + one
  back-edge example) before merge is strongly recommended, using the same
  local-headless-Chromium approach set up during this investigation
  (documented below) since no browser has reliably been available in past
  sessions.

## Headless-browser setup note (for whoever picks this back up)

No root/sudo is available in this dev environment, and
`npx playwright install --with-deps` requires it. Working alternative, used
during this investigation, that needs no root:

```
npm install playwright --no-save
npx playwright install chromium   # downloads the browser binary only, no root needed
mkdir -p localdeps && cd localdeps
apt-get download libnspr4 libnss3 libatk1.0-0t64 libatk-bridge2.0-0t64 \
  libcups2t64 libatspi2.0-0t64 libxcomposite1 libxdamage1 libxfixes3 \
  libxrandr2 libgbm1 libpango-1.0-0 libcairo2 libasound2t64
for f in *.deb; do dpkg-deb -x "$f" .; done
export LD_LIBRARY_PATH="$(pwd)/usr/lib/x86_64-linux-gnu:$LD_LIBRARY_PATH"
```

`apt-get download` fetches `.deb` files as a normal user (no install, no
root); `dpkg-deb -x` extracts them into a plain directory; `LD_LIBRARY_PATH`
points Chromium's dynamic linker at the extracted `.so` files without
touching the system. This combination successfully launched real headless
Chromium and drove `page.evaluate()`/`getComputedStyle()` checks against
the actual built course HTML in this session.

## Out of scope

- The other three v1.3.0 features (languages, non-slide sources, token
  cost) — separate design cycles.
- Any change to `array-ops`, `path-trace`, or `state-toggle` — unaffected
  by this batch.
- Branching state machines (a state with 2+ outgoing transitions) —
  explicitly considered and rejected for the reason above; a future request
  could revisit this with a different animation mechanic (e.g. multiple
  markers, or a "pick one path per loop" rotation) if it comes up.
- Adding a permanent, persistent headless-browser dependency to the test
  suite or CI — the setup above is a manual investigation/spot-check aid,
  not a new automated gate.
